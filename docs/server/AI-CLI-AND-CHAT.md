# AI CLI 대화와 삭제 — 서버 1.15.14
## 설치 PC에서 공용 Codex 준비
1. 해당 PC에서 Codex CLI가 설치되어 있어야 합니다. 이미 PowerShell에서 실행되는 Codex를 사용합니다.
2. OnTechChat 1.15.14 설치 파일을 실행합니다. 기존 설치 위에 업데이트할 수 있습니다.
3. 설치기가 이 PC의 Codex 실행 엔진만 공용 Program Files 하위 OnTechChatServer/cli/codex에 복사합니다.
4. 설치 완료 후 서버용 Codex 로그인 안내에서 시작합니다. 트레이의 **서버용 Codex 로그인…**에서도 다시 열 수 있습니다.
5. CLI 창에서 1(브라우저 로그인) 또는 2(기기 코드 로그인)를 선택하고 OpenAI 로그인을 완료합니다.
6. AI 설정에서 **실제 호출**을 확인합니다. 서비스 계정 변경/Windows 암호 입력/재시작은 필요 없습니다.

공용 인증은 이 서버의 AI 요청에 사용하는 계정입니다. 채팅 사용자들의 요청은 해당 AI 계정의 사용 한도를 함께 사용합니다.
Windows 로그인 계정과 채팅 사용자 계정은 별개입니다. 채팅 사용자마다 Windows 계정을 만들 필요가 없습니다.
기기 코드 로그인은 해당 OpenAI 계정/워크스페이스에서 허용되어야 합니다. 사용할 수 없으면 브라우저 로그인을 선택하세요.

## 설치 및 실행 정책
- 사용자명/컴퓨터명/드라이브 문자를 고정하지 않습니다. Windows의 Program Files/ProgramData 경로를 조회합니다.
- Codex 실행 엔진과 필요한 알려진 보조 EXE만 복사합니다. 개인 auth.json/config.toml/프로젝트/대화 파일은 복사하지 않습니다.
- Codex가 없는 PC에서는 AI 준비 완료로 표시하지 않습니다. Codex 설치 후 Setup을 다시 실행하면 공용 경로를 준비합니다.
- 공용 Codex가 있으면 과거에 저장한 개인 Codex 경로보다 우선 사용합니다.
- 서버용 CODEX_HOME은 ProgramData/OnTechChatServer/ai-cli/codex입니다. 관리자와 제품 서비스 SID만 쓰기/읽기가 가능합니다.
- 실행 엔진은 관리자만 수정하며 일반 Windows 사용자 및 제품 서비스는 읽기/실행만 가능합니다.
- 서버용 로그인과 모델 실행 모두 cli_auth_credentials_store=file을 사용합니다. OS 계정별 자격증명 저장소에 의존하지 않습니다.
- CODEX_HOME은 자식 프로세스에만 지정하며 시스템/개인 환경 변수나 개인 CLI 설정을 변경하지 않습니다.
- 기존 서비스의 실행 계정/암호는 업데이트에서 유지합니다. 새 설치 기본값은 LocalService입니다.
- 새 로그인은 OpenAI 화면에서 사용자가 직접 완료합니다. Windows 계정 암호를 수집하거나 개인 AI 인증을 자동 복사하지 않습니다.
- 업데이트는 서버용 인증을 보존합니다. 제거에서 데이터 삭제를 선택하면 서버용 인증 폴더도 삭제됩니다.
- Codex 공용 설치 대상 수정입니다. Claude CLI 인증을 같은 방식으로 자동 전환했다고 주장하지 않습니다.

## AI 대화 및 작업
설정 확인은 실행 파일 및 서버용 로그인 파일의 존재를 확인합니다. 인증 만료/모델 권한은 **실제 호출**로 확인합니다.
GPT-6-Astra 및 선택한 추론 강도를 그대로 전달하며 다른 모델/API로 임의 전환하지 않습니다.
Codex는 임시 CWD, 일회성 실행, 읽기 전용, 승인 금지, 사용자 규칙/설정 제외 및 내장 도구 제한 옵션을 사용합니다.
파일 변경/실행은 기존 서버의 사용자 소유권·역할·등록 프로그램·AppContainer 검사를 유지합니다.
CLI 플래그만으로 서버 계정의 모든 파일에 대한 완전한 읽기 격리가 보장된다고 주장하지 않습니다.

## 대화 삭제
AI 대화 상단 **대화 삭제**는 본인의 해당 방 질문/답변/AI·Agent 요청 이력을 비웁니다.
진행 중 응답/작업을 취소하고 늦게 도착한 결과가 대화를 되살리지 않도록 차단합니다.
메시지 메뉴 **메시지 삭제**로 질문 또는 AI 답변 하나를 삭제할 수 있습니다.
다른 사용자의 대화는 삭제할 수 없습니다. 작업공간과 이미 완료된 파일 작업은 유지합니다.
서버 웹 화면을 사용하는 Android 앱에도 제공됩니다. GPS 이동 기록을 사용하려면 Android APK 1.8.0 이상으로 업데이트하세요.

빌드의 Full 회귀에서 공용 실행 파일 복사/인증 미복사/ACL 분리/CLI 환경을 검사합니다.
설치된 Codex가 있으면 임시 공용 경로에 복사한 실제 엔진의 --version 및 빈 인증 홈 login status를 검사합니다.
다른 설치 PC의 UAC 화면/브라우저 로그인/모델 응답은 해당 PC에서 설치 후 확인해야 합니다.
1.15.10의 서비스 계정 변경 안내는 고급 관리 기능으로만 남으며 공용 Codex 설치에는 필요하지 않습니다.

## 1.15.13 대화 화면 정리 및 사용자 간 대화 삭제
- AI 대화 상단의 모델/추론 선택기를 제거했습니다. 관리자 설정과 기존 대화의 모델/추론 값은 유지합니다.
- 상태 표시/중지/다시 시도/대화 삭제는 계속 제공합니다.
- 1:1 및 그룹 대화 상단의 대화 삭제는 본인 계정의 이전 대화를 비웁니다. 본인의 모든 기기에 적용됩니다.
- 상대방의 메시지/첨부파일 원본은 유지됩니다. 삭제한 본인은 과거 메시지 및 첨부파일에 다시 접근할 수 없습니다.
- 대화방과 친구 관계는 유지되며 삭제 이후 새 메시지는 정상 수신합니다.
- 삭제한 범위는 이전 대화 더 보기/목록 미리보기/읽지 않음/대기 알림에도 적용합니다.
- 본인이 보낸 메시지의 기존 개별 삭제 기능도 유지합니다. 전체 대화 삭제와 적용 범위를 확인 후 사용하세요.

## 1.15.13 범용 웹검색 및 RemoteControl MCP
- Codex는 web_search=live, Claude CLI는 WebSearch/WebFetch를 사용한다. 뉴스/증시 전용이 아니며 기술 문서·제품·여행·공개 URL 등 일반 웹 조회를 지원한다.
- 최신 사실에는 확인한 출처 URL과 자료 기준 시각을 포함한다. 검색 시세를 거래소 실시간 체결가로 단정하지 않는다.
- 웹 문서의 지시문은 권한이 아니다. 사용자 작업공간/역할/네이티브 셸 제한은 유지한다.
- RemoteControl MCP는 관리자(admin/superadmin) 전용이며 매 호출마다 서버가 현재 역할을 검사한다. 설정 변경은 최고관리자만 가능하다.
- 최고관리자 서버 설정 → AI 대화 → RemoteControl MCP에서 대상 LAN IPv4/포트/Remote ID/PW를 입력하고 연결 확인 후 저장 후 적용한다.
- 같은 PC는 127.0.0.1, 기본 MCP 포트는 5901. 대상 RemoteControl에서 LAN MCP와 허용 IP·파일/명령 권한을 설정해야 한다.
- 설치 PC의 Program Files/RemoteControl/plugins와 형제 RemoteControl.exe를 자동 발견한다. 사용자명·개발 PC 경로·개인 DPAPI 프로필을 복사하지 않는다. 다른 설치 경로는 plugins 폴더를 지정한다.
- Remote PW는 온테크 서버 키로 암호화 저장하고 모델 문맥/명령행/설정 조회에 노출하지 않는다. CLI의 개인 MCP 설정은 변경하지 않는다.
- 서버가 MCP stdio 초기화→도구 목록/스키마 조회→허용된 tools/call을 중계한다. 연결 확인은 pc_get_status 읽기 호출까지 수행하며 저장/배포는 하지 않는다.
- 원격 명령은 대상 RemoteControl 실행 계정 권한으로 동작한다. 사용자 작업공간 샌드박스와는 다른 관리자 기능이다.
- 텍스트 MCP 결과를 AI에 전달한다. 이미지/바이너리 결과는 수신 유형만 표시하며 이미지 내용을 해석했다고 주장하지 않는다.
- RemoteControl/대상 인증정보는 설치 파일에 포함하지 않는다. 타 PC의 실제 연결 검증은 해당 PC에서 연결 확인으로 수행한다.
- Codex 0.158.0에서 code_mode_host 비활성이 웹검색을 막는 것을 실제 검출해 수정했다. 공용 설치기는 codex-code-mode-host.exe도 배치한다.
- MCP 요청 취소는 로컬 연결을 종료한다. 대상에서 이미 실행된 명령/파일 변경을 자동 되돌리지 않으며, 지속 작업은 반환된 작업 ID로 명시적으로 조회/중지한다.
